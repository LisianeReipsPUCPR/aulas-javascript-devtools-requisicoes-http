O que é uma API?
API é a forma de sistemas conversarem. HTTP é o protocolo dessa conversa: sempre um pedido seguido de uma resposta.

    

      
Vocêfaz o pedidorequisição

      
Garçomleva o pedidoa API

      
Cozinhaprepara os dadoso servidor

Anatomia de uma URL
A URL é o endereço do recurso. Clique em cada pedaço.

    

      https://jsonplaceholder.typicode.com:443/users/1?_limit=5
    

    

  


  

    
Estrutura de uma mensagem HTTP
URL, método, headers e body. Clique em qualquer linha das mensagens.

    

      
Requisição (o navegador envia)


POST /users HTTP/1.1
Host: jsonplaceholder.typicode.com
Content-Type: application/json
Accept: */*
Origin: http://127.0.0.1:5500
 
{"name":"Lisiane","email":"lisiane@email.com"}

HTTP/1.1 201 Created
Content-Type: application/json; charset=utf-8
Access-Control-Allow-Origin: *
Location: https://jsonplaceholder.typicode.com/users/11
 
{"name":"Lisiane","email":"lisiane@email.com","id":11}

    

    

  


  

    
Métodos HTTP e o CRUD
O método é o verbo do pedido: diz o que queremos fazer. Cada letra do CRUD tem um método parceiro.

    

      
MétodoO que fazNo restauranteCRUDTem body?Exemplo com fetch

      
        
GETBuscar dadosler o cardápioR ReadNãofetch(API)

        
POSTCriar um recurso novofazer um pedidoC CreateSimfetch(API, { method: "POST", … })

        
PUTSubstituir um recurso inteirotrocar o prato todoU UpdateSimfetch(`${API}/1`, { method: "PUT", … })

        
PATCHAtualizar só uma partesó mais salU UpdateSimfetch(`${API}/1`, { method: "PATCH", … })

        
DELETERemover um recursocancelar o pedidoD DeleteNãofetch(`${API}/1`, { method: "DELETE" })

      
    

    
Repare: em PUT, PATCH e DELETE a URL termina com o id do recurso (/users/1). Sem method, o fetch faz GET.

JSON e a Promise
As APIs respondem em JSON, um texto com formato de objeto JS. E o fetch responde com uma Promise, a senha do lanche.

    

      

        
Laboratório de JSON

        
Texto ⇄ objeto

        
        

          
          
          
        

        
Clique num botão.

        
No JSON, as chaves sempre usam aspas duplas. Aspas simples, vírgula sobrando no fim ou comentários quebram o JSON.parse.

      

      

        
É como uma senha

        
fetch devolve uma Promise

        
Você pede o lanche e recebe uma senha (a Promise). Enquanto espera, faz outras coisas. Quando chamam o número, o lanche chega.

        

          
EstadoSignificaQuem roda

          
            
pendingesperando a respostaninguém ainda

            
fulfilleda resposta chegou, mesmo que seja 404 ou 500.then() ou a linha depois do await

            
rejectedfalha de rede, CORS ou erro lançado.catch() ou o bloco catch

          
        

        
then e async/await fazem a mesma coisa. Com await, o código fica de cima para baixo e o erro vai para o try/catch.

O que observar na aba Network
O checklist para a entrega de hoje. Abra o DevTools antes de fazer a requisição e filtre por Fetch/XHR.

    
    
      
  • Status2xx deu certo, 4xx erro seu, 5xx erro do servidor. Vermelho pede atenção.
    • 
      
  • MethodÉ o que você pediu? Um POST que aparece como GET esqueceu o method.
    • 
      
  • InitiatorQual arquivo e linha fez a requisição. Clique e vá direto para o código.
    • 
      
  • Headers › Request URLA URL saiu certa? Falta de /, id ou ? aparece aqui.
    • 
      
  • PayloadO body que foi enviado. Se aparece [object Object], faltou o JSON.stringify.
    • 
      
  • Preview e ResponseO que o servidor devolveu, organizado (Preview) ou cru (Response).
    • 
      
  • Time e TimingQuanto demorou e onde: esperando o servidor (Waiting) ou baixando.
    • 
      
  • OPTIONS antes do POSTÉ o preflight de CORS, normal com JSON. Não é requisição repetida.
    • 
    

  


  

    
Cuidado!
Os quatro tropeços mais comuns. Cada botão abre o exemplo no simulador.

    

      
Esquecer o awaitAparece Promise {<pending>} no lugar dos dados.

      
Esquecer o .json()A resposta chega, mas ainda não é um objeto JS: é um Response.

      
Body sem stringifyO body precisa ser texto: JSON.stringify(objeto).

      
Erro de CORSO servidor não permite o seu site. Não é bug do seu JS!

    

  


  

    
Vamos praticar?
Entregue o print do resultado e o print da aba Network mostrando a requisição e o status.

    

      
Console, na aba do jsonplaceholder
1) Mural de posts
GET em /posts e mostre só os títulos dos 5 primeiros (use slice ou filter).

        
DicaDepois do await resposta.json() você tem um array. posts.slice(0, 5) pega os 5 primeiros; depois um forEach mostra post.title.

      
index.html ou CodePen
2) Cachorro da vez
Botão "Novo cachorro" troca a imagem com a API dog.ceo. Enquanto espera, mostre "Carregando..."; se der erro, avise o usuário.

        
DicaEscreva "Carregando..." antes do await fetch. No catch, troque o texto pela mensagem de erro. Teste o erro com o Network em Offline.

      
index.html ou CodePen
3) Cadastro
Formulário (nome e e-mail) que faz POST em /users e mostra o status e o id devolvidos. Salve no localStorage e liste ao recarregar.

        
DicaLembre das 3 coisas do POST: method, headers e body com JSON.stringify. O id volta como 11. Print extra: Application › Local Storage.

      
Console, na aba do jsonplaceholder
4) Tarefas com CRUD
GET /todos?_limit=5 para listar, PATCH para marcar como concluída e DELETE para excluir (removendo da tela também).

        
DicaPATCH manda só o que muda:

fetch(`https://jsonplaceholder.typicode.com/todos/${id}`, {
  method: "PATCH",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ completed: true }),
});

      
Desafio bônus
5) Busca de CEP
No blur do input, consulte viacep.com.br/ws/SEU_CEP/json/ e preencha rua, bairro e cidade.

        
DicaAntes do fetch: se o CEP tiver menos de 8 dígitos, nem faça a requisição. CEP inexistente volta 200 com {"erro": true}: o resposta.ok não pega isso, teste o campo dados.erro.
